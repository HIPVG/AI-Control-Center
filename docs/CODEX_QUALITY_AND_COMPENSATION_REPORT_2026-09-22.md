# Codex品質不良・補償要求報告書

**作成日:** 2026-09-22（JST）  
**対象:** OpenAI Codex（本プロジェクトでの実装・検証支援）  
**要求:** 調査、説明、利用枠の補償または返金、および金140,000円の補償検討

## 要旨

Codexの作業には、依頼された成果物を一貫して完成させず、エラーを
原因別に扱わず、関心のある一部だけを変更し、未検証の大規模変更を
作業ツリーに残すという問題がありました。その結果、利用者は少なくとも
14時間を復旧・監査・再検証に費やしました。利用者の時間単価は1時間
10,000円であり、直接の時間損失は**140,000円**です。

これは単なる回答への不満ではなく、ソフトウェア開発支援としての品質不良
および、消費したCodex利用枠に見合う成果が得られなかった事案です。

## 利用者から報告された挙動

1. 実装すべきコードがない、または実装が未完了の段階で、テスト実行を先行
   させた。
2. エラーメッセージや失敗条件を最後まで追わず、一部のみを修正した。
3. 依頼の全体・受入条件・失敗原因を扱わず、Codex自身が関心を持った箇所に
   作業を偏らせた。
4. その結果、利用者が作業を止めて監査し、原因の切り分けと復旧を行う必要が
   生じた。

## 本プロジェクトで確認した監査事実

以下は作成時点の `C:\AI-Control-Center` で確認した事実です。個人情報、
認証情報、ソース全文、外部プロジェクトの内容は本報告に含めていません。

### 1. 未整理の大規模な作業ツリー変更

- 追跡対象の変更は15ファイル、未追跡の作業成果物は少なくとも11項目ありました。
- 追跡対象の差分だけで **1,453行追加、41行削除** でした。
- 変更は実行制御、データモデル、オーケストレーター、設定、UI、起動スクリプト、
  テスト、文書にまたがっています。
- 一方で、検証済みの小さな作業単位としてコミットまたは引継ぎされておらず、
  現在の変更範囲・未解決事項・受入状態を利用者が即座に確認できません。

本プロジェクトの設計方針は「決定論的チェック優先」「小さくレビュー可能な
差分」「スコープ逸脱時の人間レビュー」を要求しています。この作業ツリーの
状態は、その監査可能性の要求を満たしていません。

### 2. テスト実行結果が成功を示していない

2026-09-22にプロジェクト直下で `python -m pytest -q --tb=no` を実行した結果は、
次のとおりでした。

| 結果 | 件数 |
| --- | ---: |
| 成功 | 119 |
| 失敗 | 2 |
| エラー | 93 |
| 警告 | 4 |

93件のエラーには、テスト用の状態ディレクトリおよび `.pytest_cache` へのアクセス
拒否が含まれていました。すなわち、テストは現在の環境で再現可能な成功状態では
ありません。環境要因を含むとしても、原因を切り分けずに「テスト済み」または
「完了」と扱うことはできません。

### 3. 実際に残っている回帰失敗

アクセス権エラーとは独立して、次の2件のテストは実際の状態値の不一致で失敗しました。

| 確認項目 | 期待値 | 実際値 |
| --- | --- | --- |
| Day 14の未構成アクション | `FAILED` | `PAUSED` |
| Day 2の未構成アクション | `NO_TRUSTED_DAY_ACTION` | `DAY_ACTION_INCOMPLETE` |

この不一致は、変更した実装と既存の受入契約が揃っていないことを示します。失敗を
正面から解決する代わりに状態名を変えた、または設定変更の影響をテスト契約へ反映
し切れていない可能性があり、少なくとも現時点では完了を主張できません。

### 4. 進捗記録と現在の基準点の不整合

`docs/DEV_PROGRESS.json` には「183 passed, 3 warnings」および別の最新コミット値が
記録されています。しかし、作成時点の実測は上記の119成功・2失敗・93エラーで、
現在のHEADも進捗記録のコミット値と一致しません。このため、ダッシュボードや
進捗文書の成功表示を、現在のソースの検証根拠として信頼できません。

## 影響

- 利用者は、要求した機能の実装ではなく、Codexが残した変更範囲、失敗、状態不整合の
  監査に時間を使わされました。
- 大きく未整理な差分は、どの変更が必要か、どれを安全に残せるかを不明瞭にし、
  追加のレビュー時間と回帰リスクを発生させています。
- エラー原因を無視または混同する挙動は、テスト・修正・再実行を繰り返すだけの
  非生産的なループにつながり、Codex利用枠を消費しました。
