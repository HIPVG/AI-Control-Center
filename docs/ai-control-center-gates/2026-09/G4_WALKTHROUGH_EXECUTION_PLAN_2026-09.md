# G4 限定予備ウォークスルー実施計画

文書 ID: `G4-ACC-WALKTHROUGH-20260925-001`  
状態: `EXECUTED`  
目的: M-01の主要制御経路が、既存の安全fixtureで設計どおりに働くかを確認し、M-04を実装なしに
合格扱いしない。  
根拠: 最新標準G4、`G4-ACC-20260925-001` 第10節。

## 実施順と打切り

1. W-01、W-02、W-03、W-04を既存test nodeで一回だけ実行する。
2. いずれかが失敗又は実行不能なら、その結果を記録して停止する。修正、再試行、追加fixtureはしない。
3. W-05は読取確認だけを行う。M-04の実装又は既存fixtureがなければ`NOT_EVALUABLE`とし、G3再調査の
   入力にする。
4. 実施後、G4設計書の証拠対応表と品質判定を更新する。全W-01〜W-04が合格し、W-05を未評価として
   正しく保持できた。訂正済みG4をレビューに再提示する。

## 実行境界

- 実行対象は既存の `tests/test_reviewer_bus.py` と `tests/test_local_llm_day_program.py` の指定nodeだけ。
- temporary pytest dataはAI-Control-Center内に限る。外部サービス、対象Day、モデル、実リポジトリを使わない。
- 予算・有償操作は0円。試行回数は各node一回。新規依存の導入、source編集、Git変更、fixture追加はしない。
- 失敗は技術前提の不成立又は実装差異として記録し、結果を成功へ正規化しない。

## 役割・技術手段への対応

このウォークスルーはG3の役割フローを別のフローへ置換するものではない。W-01は監視・配送と
レビュー相関、W-02は利用者入口／実行管理者／人間判断後の同一Day復帰、W-03は実装・修正担当の
停止境界、W-04は機械的検査及び証拠・状態管理を、それぞれ既存技術手段の限定された振る舞いとして
確認する。M-04の候補切替及び画面UIは確認対象に含めず、根拠がない項目を`PASS`にしない。

## 実施結果

W-01〜W-04の指定nodeは一回の限定実行で失敗・エラーなく終了した。W-05は読取確認の結果、
既存の候補切替実装又はfixtureがなく`NOT_EVALUABLE`である。新規fixture、候補切替実装、外部送達、
対象Day操作、モデル実行、費用発生、source変更は行っていない。
