## Rejection addressed

The first pack was rejected because a Day snapshot with the same Day and contract
could be projected into a different or historical RunRecord. Revision 002 changes
only that RI-01 boundary:

- `LocalLLMDaySnapshot.run_id` is an optional field so old persisted snapshots still
  load, while composed runs can carry explicit identity.
- The production composed executor passes the RI-00 run ID into the existing Day
  controller before the Day effect.
- `project_day_state` now requires the target RunRecord to be `RunStore.current()` and
  requires `snapshot.run_id` to exactly equal the target run ID before checking Day,
  contract or applying any update.
- A new assertion creates historical and current runs with the same Day and contract.
  Projection to the historical run fails `RUN_NOT_CURRENT`; projection to the current
  run from the historical snapshot fails `DAY_SNAPSHOT_RUN_ID_MISMATCH`. Both records
  are asserted byte-equivalent at the model boundary before and after each rejection.
