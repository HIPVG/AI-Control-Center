## Implemented boundary

PR-01 adds backward-readable `RunTelemetry` schema v2 and a deterministic terminal
task reconciliation boundary. Schema v1 continues to deserialize without inventing
v2 fields. Schema v2 requires sourced cached/uncached input metrics and a sourced or
explicitly unknown budget decision; gross input must equal cached plus uncached input.

Reconciliation is allowed only for the current product run and the same-run terminal
Day snapshot. Every input task must carry the exact product run ID, a unique task-run
ID, a timezone-aware terminal time, a terminal result, valid attempts and internally
consistent token totals. The result retains:

- actual attempt count and the immutable RunIntent attempt limit as separate facts;
- gross/cached/uncached/output tokens with source and observation time;
- the observed budget decision, including `TASK_BUDGET_EXCEEDED`; and
- measured cost only when every task exposes a consistent currency, otherwise an
  explicit unknown reason rather than treating the 0 JPY limit as measured cost.

Exact replay is an accepted non-writing no-op. Conflicting replay, cross-run input,
duplicate task IDs, inconsistent totals, nonterminal tasks and incomplete or
conflicting cost facts fail closed before replacing telemetry.
