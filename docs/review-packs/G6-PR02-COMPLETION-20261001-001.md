## Implemented boundary

The existing SP-00 post-save callback remains the one reconciliation boundary. For a
saved `COMPLETE` snapshot it now performs, in order:

1. exact run/contract check and strict per-criterion Evidence binding;
2. terminal task telemetry reconciliation for the same product run;
3. the existing guarded `project_day_state()` transition; and
4. ordinary durable readback through the existing stores.

Persisted Day task results receive an optional server-owned `product_run_id`. The
production callback selects only task records whose binding exactly matches the
settled run; it does not infer ownership from task names or browser/model output.
Ordinary tasks remain unbound.

Existing non-`COMPLETE` SP-00 projections remain unchanged. For COMPLETE, an Evidence
or telemetry rejection returns its concrete stage/reason without changing the prior
RunRecord. An exact telemetry replay may continue after a transient projection
failure. Once the same RunRecord is already COMPLETE, exact replay returns
`ALREADY_PROJECTED` without a second state transition. Conflicting persisted
telemetry remains fail-closed.
