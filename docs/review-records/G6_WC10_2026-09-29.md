# G6 WC-10 — read-only dashboard projection

- Selected after: exact acceptance of `G6-WC09-COMPLETION-20260929-002`
- Action class: `IMPLEMENTATION`, then bounded `VALIDATION`
- Preconditions: `WC-04_VALIDATED`, `WC-08_VALIDATED`, `WC-09_VALIDATED`
- Cost: JPY 0

Implemented a vanilla-JavaScript read-only dashboard projection over
`GET /api/local-llm/runs`. The panel displays selected Day, run ID, admission,
current state/liveness, unmet criteria, next action/blocker, review state, human
decision subject and permitted effect, separate human-response and Reviewer-
confirmation states, relay/intervention/attempt/token/cost telemetry with source or
unknown reason, and historical runs labelled as historical only.

No write binding was added. The existing selection and Go controls were not changed,
and the new projection cannot create a run, authorize Go, apply a decision, retry a
notification or change backend contracts.

Validation attempt 1 used `node --test tests/run_status_ui.test.js` and failed before
any test body ran because the Windows sandbox rejected the test runner's child-process
creation with `spawn EPERM`. This was classified as a harness restriction, not product
evidence. The fixture was then extended to check the dashboard DOM, GET-only API
binding and `app.js` syntax in the same process.

Validation attempt 2/final used `node tests/run_status_ui.test.js` and passed all four
tests. Assertions cover unselected and PREFLIGHT views; STOPPED/human-decision wait;
the approval subject/effect and pending Reviewer confirmation; interventions; unknown
tokens; sourced zero cost/relay; and history that cannot appear as current. It also
checks every required DOM target, the GET-only `/api/local-llm/runs` fetch, absence of
a POST binding, and JavaScript syntax parsing.

No service/browser was started and no backend contract, Day/Go, model, Watcher,
external send, credential, paid action, VC-11, G7/G8 or product E2E was performed.
