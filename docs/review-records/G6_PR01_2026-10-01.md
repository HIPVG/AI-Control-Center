## Implementation

- Added backward-compatible `RunTelemetry` schema v2. Schema v1 remains readable;
  v2 requires sourced cached/uncached input metrics and a sourced or explicitly
  unknown budget decision.
- Added deterministic reconciliation from terminal task facts to the current product
  run. Every task record must carry the exact product run ID, a unique task-run ID,
  a timezone-aware terminal time and a terminal result.
- Actual attempt count and gross/cached/uncached/output tokens are aggregated from
  the per-attempt records. Per-task totals must exactly equal those attempts and
  gross input must equal cached plus uncached input.
- Attempt limit comes from the immutable RunIntent. `TASK_BUDGET_EXCEEDED` is kept as
  the observed decision with source/time. Measured cost is retained only when every
  task exposes a consistent currency; otherwise it remains explicitly unknown and
  is never inferred from the zero-cost limit.
- Exact telemetry replay is an accepted no-op. A conflicting replay, cross-run task,
  duplicate task, inconsistent total, nonterminal task or partial/conflicting cost
  is rejected before replacement.
- Existing read projection exposes the v2 values and provenance under the same run
  and preserves them after reconstruction.
