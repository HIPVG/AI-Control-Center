# G6 RI-02 implementation and focused validation

## Scope

RI-02 replaces the process-startup empty run projection with a request-time
composition rooted in the persisted `RunStore`, `RunTelemetryStore`, and the
run-bound Day snapshot. It does not start a Day or infer product E2E acceptance.

## Implemented boundary

- `GET /api/local-llm/runs` asks the production engine for a fresh projection on
  every request.
- The engine composes current/history, initial admission, criteria and telemetry
  from persisted stores using the exact current run ID.
- Criteria are omitted with an explicit projection error when snapshot run ID,
  Day, contract or contract fingerprint does not match.
- Telemetry is omitted with an explicit projection error when its persisted run
  ID is unreadable or mismatched; unknown metrics remain unknown with their
  recorded reason and source.
- A corrupt run collection or version history yields no selected/current run.
  Mismatched optional review, human-decision or runtime projections are rejected
  rather than applied to the current run.
- Re-instantiated stores and controller reconstruct one current run and its
  separate history; no in-memory startup singleton is accepted as authority.
